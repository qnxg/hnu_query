# 项目结构

## 1. 顶层目录

| 路径        | 说明                                      |
| ----------- | ----------------------------------------- |
| `src/`      | 项目代码                                  |
| `docs/`     | 项目文档                                  |
| `examples/` | 示例代码                                  |
| `.env`      | 测试用环境变量，见 [`test.md`](./test.md) |
| `scripts/`  | 一些脚本                                  |

## 2. 按学校系统划分

`src` 下每一个文件夹对应学校的一个系统。名称一般为其请求接口的子域名，例如请求 `hdjw.hnu.edu.cn` 的接口放在 `src/hdjw` 下。

| 模块      | 系统                   |
| --------- | ---------------------- |
| `ca`      | 可信电子凭证平台       |
| `cas`     | 统一身份认证           |
| `gym`     | 体测系统               |
| `hdjw`    | 教务系统               |
| `lab`     | 大物实验平台           |
| `netflow` | 校园网流量系统         |
| `pt`      | 个人门户               |
| `wxpay`   | 目前只包含宿舍电量查询 |
| `xgxt`    | 学工系统               |
| `yjsxt`   | 研究生系统             |
| `ai`      | AI 大模型平台          |

### 2.1 系统域内的固定文件

学校系统对应的文件夹下，一般还会包含：

- `login.rs`：登录该系统，获得登录状态（`*Token`）
- `error.rs`：该系统特有的错误类型（如 `TokenExpired`）；没有特有错误时可省略
- `test.rs`：该系统下用于测试的配置和辅助函数（如 `get_hdjw_token()`）
- `parse.rs` / `fetch.rs`：域级共享的请求和解析相关的辅助函数（如 `hdjw::parse::hdjw_response`）

### 2.2 功能子模块：fetch / parse / mod

学校系统下还有若干子模块，对应具体接口。一个接口主要分成获取数据和解析数据两部分，因此子模块通常包含：

| 文件         | 可见性     | 职责                                                    |
| ------------ | ---------- | ------------------------------------------------------- |
| `mod.rs`     | `pub`      | 公开结构体 / 枚举、`get_*` 编排入口、集成测试           |
| `fetch.rs`   | 私有 `mod` | 网络 IO，返回原始响应（多为 `String`）                  |
| `parse.rs`   | 私有 `mod` | 纯解析，输入 `&str`，输出强类型；可附带静态数据单元测试 |
| `test_data/` | —          | 解析测试用的响应样本                                    |
